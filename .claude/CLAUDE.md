### Code Intelligence

Prefer LSP over Grep/Glob/Read for code navigation:
- `goToDefinition` / `goToImplementation` to jump to source
- `findReferences` to see all usages across the codebase
- `workspaceSymbol` to find where something is defined
- `documentSymbol` to list all symbols in a file
- `hover` for type info without reading the file
- `incomingCalls` / `outgoingCalls` for call hierarchy

Before renaming or changing a function signature, use
`findReferences` to find all call sites first.

Use Grep/Glob only for text/pattern searches (comments,
strings, config values) where LSP doesn't help.

After writing or editing code, check LSP diagnostics before
moving on. Fix any type errors or missing imports immediately.


### Project conventions

- iOS app. The Xcode project is generated by XcodeGen from `project.yml`: never edit or commit
  the `.xcodeproj`; run `xcodegen generate` after adding or removing files.
- Signing: `Config/Signing.local.xcconfig` is generated by `../ios-updater` from
  `ios-updater.conf` — don't edit it. Never change bundle ids: a new id installs an empty app
  next to the old one and consumes one of the 10 weekly app ids of the free Apple ID.
- Free Apple ID (Personal Team): no iCloud, push notifications or App Groups capabilities.
- Build and install on the iPhone: `../ios-updater/ios-updater.sh --force runmotion-exporter`.
- Swift 6 language mode, `MainActor` default isolation. Value types used from SwiftData models
  or other nonisolated code must be declared `nonisolated` (and `Sendable`).
- Tests: Swift Testing (`import Testing`), not XCTest.
  `xcodebuild test -project runmotion_exporter.xcodeproj -scheme runmotion_exporter -destination 'platform=iOS Simulator,name=<iPhone>'`
- Lint must pass before committing: `swiftlint lint --strict --baseline .swiftlint-baseline.json`.
  Fix new violations; don't regenerate the baseline to hide them.
- If `xcode-select -p` points to the Command Line Tools, prefix xcodebuild/swiftlint with
  `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.
- Commits: Conventional Commits (`feat:`, `fix:`, `ci:`…) — `release.yml` derives the version
  bump from them. CI workflow name must stay `Test`.
